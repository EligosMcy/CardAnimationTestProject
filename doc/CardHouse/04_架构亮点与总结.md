## 1. Gate 门控系统

### 源码位置

[Gate.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Gates/Gate.cs)、[GateCollection.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Gates/GateCollection.cs)

### 设计理念

Gate 是 CardHouse 的**合法性校验框架**——所有关键操作（拖拽启动、放下、点击、目标选择）都必须经过 Gate 的"关卡"检查。Gate 的最大优势是**可插拔**：新增规则不需要修改核心代码，只需创建新的 Gate 子类。

```
┌─────────────────────────────────────────────────────────────┐
│                    Gate 系统全景                             │
└─────────────────────────────────────────────────────────────┘

  DragDetector.OnMouseDown()
    │
    ├── DragGates.AllUnlocked(null)  ← 一组 Gate
    │     │
    │     ├── Gate1: 玩家是否有足够法力？
    │     ├── Gate2: 当前阶段是否允许拖拽？
    │     └── Gate3: 卡牌本身是否可拖拽？
    │
    └── 全部通过 → 触发 OnDragStart

  CardGroup.HandleDragDrop()
    │
    ├── DropGates.AllUnlocked(dropParams)   ← 目标 Group 的门
    ├── GroupDropGates.AllUnlocked(dropParams)  ← 源卡的门
    └── TargetCardGates.AllUnlocked(targetParams)  ← 目标卡的门
    │
    └── 全部通过 → 执行挂载/弃牌
```

### Gate 基类

```csharp
public abstract class Gate<T> : Toggleable
{
    public bool IsUnlocked(T argObject)
    {
        if (!IsActive) return true;  // 未激活的 Gate 视为"已解锁"
        return IsUnlockedInternal(argObject);
    }

    protected abstract bool IsUnlockedInternal(T argObject);
}
```

### Gate 类型

| Gate 类型 | 泛型参数 | 用途 |
|-----------|---------|------|
| `Gate<NoParams>` | 无参数 | 简单布尔检查（阶段、状态） |
| `Gate<DropParams>` | 拖拽信息 | 放下合法性检查 |
| `Gate<TargetCardParams>` | 目标卡信息 | 目标卡合法性检查 |

### 实际用例：SolitaireColumnDropGate

**源码**：[SolitaireColumnDropGate.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/SampleGames/Solitaire/Scripts/SolitaireColumnDropGate.cs)

```csharp
public class SolitaireColumnDropGate : Gate<DropParams>
{
    protected override bool IsUnlockedInternal(DropParams gateParams)
    {
        var topCard = gateParams.Target.Get();
        var pokerCard = gateParams.Card.GetComponent<PokerCard>();

        if (topCard == null)
            return pokerCard.Rank == 13;  // 空列只能放 K

        var topPokerCard = topCard.GetComponent<PokerCard>();
        return !IsColorMatch(pokerCard, topPokerCard) 
               && pokerCard.Rank == topPokerCard.Rank - 1;  // 红黑交替、点数递减
    }
}
```

这个 Gate 实现了完整的纸牌接龙放下规则，**完全不需要修改 CardHouse 核心代码**。

## 2. Phase 回合阶段系统

### 源码位置

[PhaseManager.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Phases/PhaseManager.cs)、[Phase.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Phases/Phase.cs)

### 设计理念

Phase 是回合制游戏的**状态机骨架**。每个阶段定义了：谁的回合、镜头位置、允许的操作、自动执行的事件链。

```csharp
public class Phase
{
    public string Name;
    public int PlayerIndex;
    public Transform CameraPosition;            // 阶段开始时镜头移动到这里
    public Transform CardPresentationPosition;   // 卡牌展示位置
    public List<Button> ActiveButtons;           // 本阶段激活的按钮
    public List<ClickDetector> ValidClickTargets; // 本阶段可点击的目标
    public List<DragTransition> ValidDrags;      // 本阶段允许的拖拽
    public List<TimedEvent> OnPhaseStartEventChain;  // 阶段开始事件链
    public List<TimedEvent> OnPhaseEndEventChain;    // 阶段结束事件链
}
```

### 阶段流转示意

```
┌──────────┐    NextPhase()    ┌──────────┐
│ Phase A  │ ────────────────→ │ Phase B  │
│ 玩家1回合 │                   │ 玩家2回合 │
└──────────┘                   └──────────┘
     │                              │
     ├── Camera → Position_A        ├── Camera → Position_B
     ├── 激活按钮 [B1, B2]          ├── 激活按钮 [B3]
     ├── 禁用 [B3]                  ├── 禁用 [B1, B2]
     ├── ValidDrags:                ├── ValidDrags:
     │   Source A → Dest X          │   Source B → Dest Y
     │   Source A → Dest Y          │   Source B → Dest Z
     └── OnPhaseStart 事件链        └── OnPhaseStart 事件链
```

### PhaseManager 核心逻辑

```csharp
public class PhaseManager : MonoBehaviour
{
    public List<Phase> Phases;
    public Phase CurrentPhase => Phases[CurrentPhaseIndex];

    public void NextPhase()
    {
        // 1. 禁用所有按钮
        foreach (var button in AllPhaseDependentButtons)
            button.interactable = false;

        // 2. 执行当前阶段 End 事件链
        // 3. 切换到下一阶段
        // 4. 执行新阶段 Start 事件链（含镜头切换）
        // 5. 激活新阶段的按钮
    }

    // 校验拖拽合法性
    public bool IsValidDrag(CardGroup source, CardGroup destination, DragAction dragAction)
        => CurrentPhase.ValidDrags.Any(x => 
            x.Source == source && x.Destination == destination && x.DragAction == dragAction);
}
```

## 3. Currency 资源系统

### 源码位置

[CurrencyWallet.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Currencies/CurrencyWallet.cs)、[CurrencyUI.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Currencies/CurrencyUI.cs)、[CurrencyChangeDetector.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Currencies/CurrencyChangeDetector.cs)

### 设计理念

内置资源/费用系统，支持"出牌消耗法力值"等机制，无需自行实现。

```
┌───────────────────────────────────────────────────────────┐
│                   Currency 系统架构                       │
└───────────────────────────────────────────────────────────┘

  CurrencyWallet (MonoBehaviour)
    │  存储货币：Dictionary<string, CurrencyQuantity>
    │
    ├── CurrencyChangeDetector
    │     检测变化 → 触发 OnCurrencyChanged 事件
    │
    ├── CurrencyUI
    │     订阅变化事件 → 自动更新 UI 显示
    │
    ├── IncrementCurrencyOperator (Activatable)
    │     → 增加指定货币
    │
    └── CurrencyCost (Gate)
          → 检查是否有足够货币（作为 Gate 使用）
```

### 核心组件

| 组件 | 职责 |
|------|------|
| `CurrencyWallet` | 存储和管理货币余额 |
| `CurrencyChangeDetector` | 检测变化并广播事件 |
| `CurrencyUI` | 自动同步 UI 显示 |
| `IncrementCurrencyOperator` | 增加货币的 Operator |
| `CurrencyCost` | 作为 Gate 检查是否有足够货币 |
| `CurrencyRegistry` | 全局货币注册表 |

## 4. 事件链与条件响应

### TimedEvent 事件链

**源码**：[TimedEvent.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Events/TimedEvent.cs)、[EventChain.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Events/EventChain.cs)

`TimedEvent` 是 CardHouse 的**时序编排系统**，用于实现"卡牌 A 播放完→卡牌 B 播放"的顺序执行。

```csharp
// EventChain 触发时序事件
public class EventChain : MonoBehaviour
{
    public List<TimedEvent> Events;
    public UnityEvent OnChainFinished;

    public void Activate()
    {
        StartCoroutine(TimedEvent.ExecuteChain(Events, () => OnChainFinished?.Invoke()));
    }
}
```

### GroupConditional 条件响应

**源码**：[GroupConditional.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/ConditionalOperators/GroupConditional.cs)

根据卡牌当前所在的 Group，触发不同的响应：

```csharp
public class GroupConditional : Activatable
{
    public Card MyCard;
    public List<GroupNameUnityActionKvp> Responses;  // GroupName → UnityEvent 映射

    protected override void OnActivate()
    {
        foreach (var kvp in Responses)
        {
            if (kvp.Key == GroupRegistry.Instance?.GetGroupName(MyCard.Group))
                kvp.Value.Invoke();  // 只触发匹配的那一个
        }
    }
}
```

**示例**：卡牌在"手牌"Group 时激活触发"准备出牌"，在"弃牌堆"Group 时触发"消耗效果"。

## 5. 卡牌正反面与朝向

### Flip 翻牌

**源码**：[Card.cs#L71-L93](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Card/Card.cs#L71-L93)

```csharp
public void SetFacing(CardFacing facing, bool immediate = false, float spd = 1f)
{
    if (facing == CardFacing.None) return;
    FlipAnimator.SetBool("SkipAnimation", immediate);
    FlipAnimator.SetBool("FaceUp", facing == CardFacing.FaceUp);
    FlipAnimator.speed = spd;

    if (facing == CardFacing.FaceUp) OnFlipUp?.Invoke();
    else if (facing == CardFacing.FaceDown) OnFlipDown?.Invoke();
}
```

使用 `Animator` 控制翻牌，配合 `FaceHoming/FaceTurning/FaceScaling` 独立于卡本身的"面"组件。

### UpsideDown 倒置

**源码**：[Card.cs#L95-L106](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Card/Card.cs#L95-L106)

```csharp
public void SetUpsideDown(bool isUpsideDown)
{
    if (!CanBeUpsideDown) return;
    var currentRotation = RootToRotateWhenUpsideDown.localRotation.eulerAngles;
    currentRotation += Vector3.forward * ((isUpsideDown ? 180f : 0f) - ...);

```

支持塔罗牌等场景中随机倒置，`Shuffle` 时自动根据 `UpsideDownChance` 随机触发。

## 6. GroupRegistry 全局注册表

### 源码位置

[GroupRegistry.cs](file:///c:/Project/CardAnimationTestProject/Assets/CardHouse/CardHouseCore/Scripts/Groups/GroupRegistry.cs)

`GroupRegistry` 是全局 Group 注册表，提供了按名称和玩家索引查找 Group 的能力：

```csharp
public class GroupRegistry : MonoBehaviour
{
    public List<NamedGroup> Groups;  // Name + PlayerIndex + Group 映射

    public CardGroup Get(GroupName name, int? playerIndex)
    {
        foreach (var group in Groups)
            if ((playerIndex == null || group.PlayerIndex == playerIndex) 
                && group.Name == name)
                return group.Group;
        return null;
    }

    public int? GetOwnerIndex(CardGroup group)
    {
        foreach (var namedGroup in Groups)
            if (namedGroup.Group == group)
                return namedGroup.PlayerIndex;
        return null;
    }
}
```

**支持的 GroupName**：

```
GroupName:
  - Deck（牌库）
  - Hand（手牌）
  - Discard（弃牌堆）
  - Field（场上）
  - Target（目标）
  - ... 可自定义扩展
```

**使用场景**：
- 出牌时自动找到弃牌堆：`GroupRegistry.Instance.Get(GroupName.Discard, playerIndex)`
- 判断卡牌归属：`GetOwnerIndex(card.Group)` → 玩家索引
- Loyalty 判断：自己的牌 vs 对方的牌

## 7. 设计模式总结

CardHouse 综合运用了以下设计模式：

### 策略模式（Strategy）

| 应用 | 实现 |
|------|------|
| 运动策略 | `Seeker<T>` → Exponential/Instant/Waypoint 等 |
| 布局策略 | `CardGroupSettings` → Splay/Stack/Slot/Grid |
| 挂载策略 | `MountingMode` → Top/Bottom/Closest |
| 拖拽行为 | `DragAction` → Mount/UseAndDiscard/UseOnTarget |

### 观察者模式（Observer）

| 应用 | 实现 |
|------|------|
| 拖拽广播 | `Dragging.OnDrag/OnDrop/PostDrop` |
| 聚焦广播 | `Card.OnCardFocused` 静态事件 |
| Group 变化 | `CardGroup.OnGroupChanged` |
| 货币变化 | `CurrencyChangeDetector.OnCurrencyChanged` |
| 阶段切换 | `PhaseManager.OnPhaseChanged` |

### 命令模式（Command）

| 应用 | 实现 |
|------|------|
| 时序编排 | `TimedEvent` / `EventChain` |
| 操作执行 | `Activatable` 抽象基类 |
| 卡牌操作 | `CardTransferOperator` / `DiscardCardOperator` / `ShuffleOperator` |

### 状态模式（State）

| 应用 | 实现 |
|------|------|
| 回合状态机 | `PhaseManager` + `Phase` |
| 交互开关 | `Toggleable.IsActive` |
| 拖拽状态 | `Dragging.IsDragging` |

### 模板方法模式（Template Method）

| 应用 | 实现 |
|------|------|
| Seeker 组件 | `BaseSeekerComponent<T>` → 子类实现 `GetCurrentValue`/`SetNewValue` |
| Gate 校验 | `Gate<T>` → 子类实现 `IsUnlockedInternal` |
| 布局策略 | `CardGroupSettings` → 子类实现 `ApplySpacing` |

### 核心优势总结

| 优势 | 说明 |
|------|------|
| **零 GC 压力** | Seeker 使用 struct 计算，不产生垃圾分配 |
| **全 Inspector 配置** | 大部分行为可在编辑器配置，无需编码 |
| **强扩展性** | 新增布局/门控/策略只需继承基类 |
| **物理精准碰撞** | 基于 Collider2D + 物理回调，不依赖 UI EventSystem |
| **多玩家支持** | GroupRegistry + Phase 支持多玩家回合制 |
| **动画策略分离** | 移动/旋转/缩放与业务逻辑完全解耦 |
| **事件驱动通信** | 静态事件实现松耦合，各模块独立演化 |
| **可测试性** | Gate 和 Seeker 可独立单元测试 |

### 与其他框架对比

| 特性 | CardHouse | Unity UI | DOTween |
|------|-----------|----------|---------|
| 卡牌交互 | ✅ 内建 Drag/Click/Hover | ❌ 需自定义 | ❌ 仅动画 |
| 布局策略 | ✅ 4+ 种内建布局 | ❌ 需手写 | ❌ 无 |
| 门控系统 | ✅ Gate 可插拔 | ❌ 需自定义 | ❌ 无 |
| 回合阶段 | ✅ Phase 内建 | ❌ 需自定义 | ❌ 无 |
| 资源系统 | ✅ Currency 内建 | ❌ 需自定义 | ❌ 无 |
| 动画系统 | ✅ Seeker 策略模式 | ❌ 有限 | ✅ Tween 引擎 |
| 3D 空间 | ✅ 原生支持 | ❌ 仅 UI Canvas | ⚠️ 有限 |
| 学习曲线 | 中等 | 低 | 低 |
