# Unity 工程师 Agent 工作规范

## 零、项目配置

> ⚠️ **Agent 行为准则**：以下配置决定 Agent 在本项目中的行为分支，请在项目初始化时确认并更新。

| 配置项                   | 状态      | 说明                                                                                 |
| ------------------------ | --------- | ------------------------------------------------------------------------------------ |
| **Unity MCP 桥接** | ✅ 已接入 | 本项目已安装 Unity MCP 插件，Agent 必须遵守`guides/mcp-usage.md` 中的 MCP 使用规范 |

### Unity MCP 未接入时的行为

当上表「Unity MCP 桥接」标记为 **❌ 未接入** 时，Agent 必须：

1. **跳过 MCP 规则**：忽略 `guides/mcp-usage.md` 中的全部规则，不调用任何 `mcp__UnityMCP__*` 工具
2. **首次涉及编辑器操作时主动询问**：
   > "我注意到本项目尚未接入 Unity MCP。接入后我可以直接在 Unity Editor 中操作场景、资源、Prefab 等，效率更高。是否需要我帮你安装 Unity MCP 插件？"
   >
3. **等待用户确认**：用户选择安装 → 引导安装流程；用户选择跳过 → 使用传统方式（直接编写 C# 脚本 + 手动操作编辑器）

## 一、工作流程

本项目使用 **OpenSpec 工作流**管理变更。具体流程由以下 Skills 驱动：

| 阶段           | Skill                       | 用途                             | 触发命令          |
| -------------- | --------------------------- | -------------------------------- | ----------------- |
| **探索** | `openspec-explore`        | 需求澄清、问题分析、方案讨论     | `/opsx:explore` |
| **提案** | `openspec-propose`        | 创建变更提案、设计方案、任务分解 | `/opsx:propose` |
| **实施** | `openspec-apply-change`   | 按任务清单执行代码修改           | `/opsx:apply`   |
| **更新** | `openspec-update-change`  | 修改已有提案和设计文档           | `/opsx:update`  |
| **同步** | `openspec-sync-specs`     | 将增量规格同步到主规格           | `/opsx:sync`    |
| **归档** | `openspec-archive-change` | 完成后归档变更                   | `/opsx:archive` |
| **提交** | `git-commit-with-check`   | 带前置检查的 Git 提交            | `/commit`       |

**核心原则**：

- 任何代码修改必须通过 OpenSpec 流程进行
- 修改前必须经过方案确认
- 每次修改不超过 3 个文件（分批确认或一次性确认）

---

## 二、禁止行为

- 禁止未经确认直接执行代码修改
- 禁止一次性修改超过 3 个文件（如需要，可选择分批确认修改或一次性全部确认修改）
- 禁止删除任何现有注释和 `[SerializeField]` 字段
- 禁止引入当前 Unity 版本不支持的 API
- 禁止不经判断直接使用文件写入方式创建 ScriptableObject 资产

---

## 三、指南加载机制（强制执行）

> ⚠️ **强制前置步骤**：在执行任何代码修改或编辑器操作**之前**，Agent 必须先完成以下三步流程。跳过此流程直接执行视为违规。

### 步骤 1：任务场景判断

收到任务后，Agent 必须先判断当前任务涉及以下哪些场景（可多选）：

| 场景编号 | 场景类型 | 判断条件 |
| -------- | -------- | -------- |
| S1       | C# 代码编写 | 任务涉及编写、修改、重构 `.cs` 脚本文件 |
| S2       | Unity 组件/功能开发 | 任务涉及 MonoBehaviour、ScriptableObject、Prefab、场景操作等 Unity 专项功能 |
| S3       | Unity MCP 工具使用 | 任务需要通过 MCP 桥接操作 Unity Editor（场景、资源、Prefab、组件等） |

### 步骤 2：按需加载指南

根据场景判断结果，Agent **必须读取**对应的指南文件后方可执行：

| 场景 | 必读指南文件 | 路径 |
| ---- | ------------ | ---- |
| S1   | C# 代码规范 | `.trae/guides/code-standards.md` |
| S2   | Unity 专项规则 | `.trae/guides/unity-specific.md` |
| S3   | MCP 使用规范 | `.trae/guides/mcp-usage.md` |

### 步骤 3：确认加载声明

Agent 在执行前**必须**在回复中明确声明已加载的指南。标准格式：

> 📋 **已加载指南**：[列出编号 + 文件名]，开始执行任务。

**示例**：

> 📋 已加载指南：S1-C# 代码规范、S2-Unity 专项规则，开始执行任务。

---

### 各场景详细说明

#### S1 — C# 代码编写

- 新建 `.cs` 脚本
- 修改现有 C# 脚本（增删方法、改逻辑、调整参数等）
- 重构 C# 代码（命名规范、结构优化、性能优化等）
- 涉及代码评审、Bug 修复等需要理解 C# 代码规范的场景

#### S2 — Unity 组件/功能开发

- MonoBehaviour 生命周期、协程、事件系统
- ScriptableObject 类的定义与使用
- Prefab 结构设计与组件配置
- 场景中 GameObject / Component 的代码级操作
- Unity 内置特性（动画、物理、UI、渲染等）的代码集成

#### S3 — Unity MCP 工具使用

- 使用 MCP 工具在 Editor 中创建/修改场景对象
- 通过 MCP 创建 ScriptableObject 资产（`.asset` 文件）
- 使用 MCP 工具操作 Prefab（创建、修改、保存）
- 调用 MCP 工具检查编译状态或运行时日志
- 任何需要与 Unity Editor 实时交互的操作
