# Git Commit With Check

## 前置条件

使用此 Skill 前，确认项目已配置 Unity MCP 连接（用于检查编译错误和场景保存）。若无 MCP 连接，则跳过编辑器检查步骤。

## 工作流程

### 第零步：选择提交模式

1. **询问用户选择提交模式**：
   > "请选择提交模式：
   > - 全自动模式：Unity场景自动保存、所有文件自动暂存、自动生成日志、自动提交、自动推送，全程无需确认
   > - 手动模式：每步需用户确认后执行"

2. **记录用户选择**，后续步骤根据模式执行不同逻辑：
   - **全自动模式**：跳过所有确认环节，直接执行操作
   - **手动模式**：按原有逻辑，每步需用户确认

### 第一步：检查当前状态

1. **检查 Unity 编译错误**（如果有 Unity MCP 连接）：
   - 调用 `read_console` 查看 Unity Editor 控制台
   - 若有编译错误，列出错误列表，**无论什么模式都必须询问用户是否修复后再提交**（编译错误为硬阻断条件）
   - 若用户选择修复，退出此 Skill 流程，进入修复模式

2. **检查场景是否保存**：
   - 若有 Unity MCP 连接：
     - 调用 `manage_editor(action="check_scene_saved")` 或类似工具检查当前场景是否已保存
     - 若未保存，直接调用 `manage_scene(action="save")` 保存场景，无需询问用户
   - 若无 Unity MCP 连接：
     - **手动模式**：询问用户确认场景是否已手动保存
     - **全自动模式**：提示"未检测到 Unity MCP 连接，场景保存状态未经验证，请确保场景已手动保存"，然后继续执行

3. **检查 Git 状态**：
   - 运行 `git status` 查看所有文件状态
   - **检查暂存区**：根据 `git status` 判断是否有未添加到暂存区的文件（包括未跟踪文件、已修改但未暂存的文件）
     - **手动模式**：若有未暂存文件，询问用户：
       > "有文件未添加到暂存区，是否全部添加到暂存区？还是由你手动添加？"
       - 若用户选择**全部添加** → 执行 `git add` 添加所有未暂存文件
       - 若用户选择**手动添加** → 告知用户手动添加完成后通知我继续
       - 若所有变更已在暂存区 → 继续
     - **全自动模式**：直接执行 `git add -A` 添加所有未暂存文件（包括未跟踪文件）
   - 运行 `git diff --cached` 查看已暂存的具体变更内容
   - 运行 `git log --oneline -5` 查看最近提交信息，了解仓库提交风格

### 第二步：编写提交日志

1. 分析所有变更内容，分类总结：
   - 新增文件
   - 修改文件
   - 删除文件

2. **草拟提交信息**：
   - 使用 Conventional Commit 格式：`<type>(<scope>): <description>`
   - type 类型：`feat`（新功能）、`fix`（Bug修复）、`refactor`（重构）、`docs`（文档）、`chore`（杂项）
   - scope：涉及的系统模块名称
   - 描述简洁明了，用中文写明修改内容

3. **展示提交信息给用户审批**：
   ```
   提交信息：
   <type>(<scope>): <description>
   
   变更文件清单：
   - <路径>：<变更说明>
   ```
   
   - **手动模式**：询问用户："请确认以上提交信息是否合适，或告诉我需要修改的内容。"，等待用户确认后继续
   - **全自动模式**：直接使用生成的提交信息，无需用户确认，继续执行

### 第三步：执行提交

1. **手动模式**（用户已确认提交信息）：
   - 使用 `git add <files>` 添加需要提交的文件（具体文件名，不要用 `git add -A`）
   - 使用 `git commit -m "<message>"` 执行提交
   - 运行 `git status` 确认提交成功

2. **全自动模式**：
   - 使用 `git commit -m "<message>"` 执行提交
   - 运行 `git status` 确认提交成功

3. 提交完成后：
   - **手动模式**：询问用户："提交已完成，是否需要推送到远程？"
   - **全自动模式**：直接进入第四步推送

### 第四步：推送

1. **手动模式**（用户已确认推送）：
   - 检查当前分支是否有远程跟踪：`git branch -vv`
   - 若无远程跟踪，使用 `git push -u origin <branch>`
   - 若有远程跟踪，使用 `git push`

2. **全自动模式**：
   - 检查当前分支是否有远程跟踪：`git branch -vv`
   - 若无远程跟踪，使用 `git push -u origin <branch>`
   - 若有远程跟踪，使用 `git push`

3. 推送完成后通知用户。

## 注意事项

- **手动模式**：不要使用 `git add -A` 或 `git add .`，优先使用具体文件名
- **全自动模式例外**：全自动模式下使用 `git add -A` 添加所有未暂存文件，包括未跟踪文件
- **编译错误硬阻断**：无论什么模式，若有编译错误必须询问用户是否修复后再提交，这是安全问题而非确认问题
- **手动模式**：不要在未获得用户明确确认前执行提交或推送
- **全自动模式**：跳过所有确认环节，直接执行操作
- 若有 Unity MCP 连接异常，跳过编辑器检查步骤，告知用户需手动确认
- 不要修改 git config
- 不要使用 `git push --force`
